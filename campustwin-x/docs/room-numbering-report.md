## 4. 重新生成与自校验

- 运行方式:`node tools/etl/gen-simulation.mjs`(种子 mulberry32(20250520),可复现)。
- 注意:生成器会把现有 rooms.json **全部当样例保留**,故先把 rooms.json 裁回 12 个真实样例(头部 12 条,id 断言校验)再重新生成。
- 结果:**510 间**(原 509)。+1 原因:旧样例名 `信电楼401实验室` 与生成器实验室条目同名,曾致 4 楼一间实验室被去重跳过;更名后正常生成,属缺陷修复。
- 自校验(脚本检查,模拟 floorLayout 的 roomNumber 解析):
  - id 全局唯一 ✓;同楼 name 唯一 ✓
  - 三位数字号楼层位 = floor 字段 ✓(如 5xx 均在 5 楼)
  - 每层楼内序号(末两位/中文序号)不重复且连续 1..k ✓(唯一例外:图书馆每层仅 1 间,号即楼层,如「三楼阅览室」,非序列,符合真实习惯)
- 与布局引擎匹配:floorLayout `sortRooms` 按 name 首个数字升序、奇数分北/西侧、偶数分南/东侧;每层 01–08(教学楼)/01–06(信电楼)连续编号 → 沿走廊一端起排、奇偶分侧,与真实教学楼习惯一致。

## 6. 遗留风险

1. **每层房间数为仿真设定**(教学楼 8 间/层),与真实各楼教室数(A45/B34/C49…)不一致;真实 C 楼 1 层门牌到 132 且有跳号。如需进一步拟真,需按楼定制每层数量与跳号表——属数据量扩充,不影响编号规则正确性。
2. **门牌是否带字母前缀**:官方文件写「A教学楼217教室」,推测门牌本身为三位数字、楼名前置于楼体标识;`C302` 为课表/口语合写形式。此点无门牌照片直接证据,为合理推断。
3. **奇偶分侧**为高校通行惯例 + floorLayout 设计,未查到浙商大明文规定。
4. 信息楼、网络信息中心、环境楼、东语楼、艺术楼**未检索到具体房号实例**,沿用了信电楼/经济楼已验证的「楼名+楼层+序号」同构规则(推断成分)。
5. 食品楼真实别名为「贝因美楼」、另有「逸夫楼」教室(逸夫楼123),buildings.json 未含这些名称;若后续要别名可搜索,需改 buildings.json 的 name/alias(本次任务范围外,未动)。
6. 艺术楼真实有负一层(艺术楼负一层103),当前仿真从 1 层起编;如加地下层需动 buildings.json levels 与生成器循环。
