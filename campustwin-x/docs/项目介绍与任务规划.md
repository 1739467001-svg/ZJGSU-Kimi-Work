## 一、项目介绍

### 1.1 一句话定位

**浙江工商大学下沙校区的 3D 数字孪生智能平台**——把整个校园搬进浏览器:
真实布局的 3D 场景、真实太阳驱动的昼夜循环、可对话的 AI 指挥台。

### 1.2 核心能力

| 模块 | 能力 |
|---|---|
| **3D 校园** | 基于 OpenStreetMap 真实布局烘焙:422 栋楼宇、道路、水系、733 棵树木、21 处地标 |
| **地标精模** | 综合大楼(新月形弧板 + 12m 全透明玻璃金字塔 + 环形喷泉)、图书馆白色主塔、信电楼、文体中心、南门飞翔门(展翅海鸥)、北门地球门(凯旋门 + 自转地球仪) |
| **真实昼夜** | suncalc 真实太阳方位;黎明/白天/黄昏/夜晚自动流转;"自动"模式 600 倍速全日循环演示(约 2.4 分钟一天);黄昏按钮动态锁定当日日落前 25 分钟(随季节漂移) |
| **气象与四季** | 雨/雪/雾天气、季节变化、晴雾控制 |
| **人流仿真** | 课程表驱动的房间占用、潮汐人流、食堂排队、图书馆占座、能耗累计 |
| **AI 指挥台** | 一句话指挥校园:找空会议室、报修、校园态势、带我逛校园、导航问路、天气/昼夜/画质控制;支持**语音输入**(Web Speech API,zh-CN) |
| **场景生命力** | 流动云层(黄昏染暖、深夜淡出)、飞鸟群(黎明黄昏最活跃)、旗帜飘动、喷泉、夜间全灯 |
| **数据源适配层** | `src/lib/datasource/` 预留 HttpDataSource,未来接学校预约/工单/能耗真实后端仅需一行配置 |

### 1.3 技术栈与架构

- **前端**:React 19 · TypeScript · Vite 8 · Three.js / @react-three/fiber / drei · zustand · ECharts
- **构建产物**:纯静态 SPA(`dist/`),无需 Node 运行时;已分包(业务入口 145KB + three/echarts/react vendor 长缓存)
- **云部署**:`Dockerfile`(多阶段构建 → Nginx)+ `nginx.conf`(SPA 回退/gzip/缓存策略)+ `DEPLOY.md`(Docker / 手动 Nginx / 静态托管三种方式)
- **演示参数**:`?t=HH:MM` 锁定时刻 · `?q=low|medium|high` 锁画质 · `?mode=workbench` 定模式

### 1.4 质量保障

- TypeScript 严格模式,`tsc -b` + `vite build` 双口径零报错
- AI 指令链路回归脚本:45 句真实语料解析 45/45、端到端链路断言 16/16(`scripts/verify-*.cjs`)
- 每个里程碑截图验收(日景/夜景/黄昏/工作台)

## 二、任务规划

### 2.1 已完成里程碑

| 阶段 | 内容 | 状态 |
|---|---|---|
| **M0** | 项目脚手架、OSM 数据烘焙管线、灰盒校园 | ✅ |
| **M1** | 3D 场景主体:楼宇/地面/道路/水系/植被、轨道相机 | ✅ |
| **M2** | 昼夜系统、夜景全灯、AI 指令面板四条核心链路、画质分档 | ✅ |
| **M3 第一轮** | 白天模式真实化(suncalc 修复)、综合大楼/图书馆/信电楼精模重建、昼夜切换按钮 | ✅ |
| **M3 第二轮** | 指令链路 45/45 验收、电影感开场运镜、天空曝光与色彩校正、构建分包、语音输入 + 数据源适配层 | ✅ |
| **M3 第三轮** | 动态黄昏/夜晚 + 自动 24h 循环、综合楼透明 bug 根治 + 12m 玻璃金字塔、飞翔门/地球门重建、云层/飞鸟/旗帜、全场景色彩校正 | ✅ |
| **部署准备** | Docker + Nginx 配置、DEPLOY.md、GitHub 同步约定落地 | ✅ |

### 2.2 下一步规划(按优先级)

| # | 任务 | 说明 | 依赖 |
|---|---|---|---|
| P0 | **云服务器上线** | 按 DEPLOY.md 部署到自有云服务器;域名 + HTTPS(语音输入必需) | 用户提供服务器与域名 |
| P0 | **真机视觉走查** | 开场运镜手感、正午天空湛蓝度、黄金时刻戏剧化程度(参数偏保守,可加重)、金字塔玻璃质感 | 用户在真浏览器反馈 |
| P1 | **白色斑块排查** | 综合大楼东南、图书馆南侧地面的白色像素块,疑似树木/地被白天材质异常 | — |
| P1 | **屋顶描边确认** | 白天部分楼宇的橙/青色轮廓线来源待确认,若非刻意设计应关闭 | — |
| P1 | **北门地球仪校准** | 调研未找到地球仪现状照片,当前为文献推断造型;实地补拍后精确校准 | 用户实地照片 |
| P2 | **校园细节完善** | 运动场(篮球场/田径场看台)、中轴大道景观、道路标线、行道树种类多样化 | — |
| P2 | **巡游逐站镜头** | "带我逛校园"目前只有全校镜头联动,逐站 waypoint 巡航待 3D 侧开发 | — |
| P2 | **天空地平线观感** | Preetham 模型近地平线偏白,可加地平线霾色微调 | — |
| P3 | **M4 真实数据接入** | 通过 datasource 适配层接学校真实课表/预约/工单/能耗 API;语音识别需 HTTPS 环境验证 | 学校数据源开放 |
| P3 | **性能深化** | WeatherFX/RainSnow 懒加载评估;vendor chunk >500KB 警告处理 | — |

### 2.3 长期愿景

1. **从"演示孪生"到"运行孪生"**:接入真实校园数据流,让平台反映校园每一刻的真实状态
2. **从"看"到"管"**:能耗分析、安防告警、活动保障等运营级应用
3. **从"一个校区"到"一套方法"**:把数据烘焙管线与孪生框架沉淀为可复用方案,任何校园皆可接入
